# Excel workbooks and backup format

## Private workbook – `Sofies-Regnskab-YYYY-MM-DD.xlsx`

Complete, readable outside the app, and structured enough to rebuild all data.

| Sheet | Content |
|---|---|
| Overblik | Human-readable: per-year totals (sessions, session value, received, outstanding, expenses, km) and explanations. |
| Sessioner | ID, Dato, Klient (kaldenavn), Sessionselementer, Varighed (min.), Varighed, Pris, Betalt, Udestående, Oprettet/Ændret (UTC). |
| Sessionselementer | Session-ID, Dato, Nr. (1–3), Element-ID, Element. |
| Betalinger | ID, Session-ID, Sessionsdato, Betalingsdato, Beløb, Metode-ID, Metode, Klient, Oprettet/Ændret. |
| Udgifter | ID, Dato, Beløb, Kategori-ID, Kategori, Beskrivelse, receipt path in the backup, receipt id/name/type/size/SHA-256, Oprettet/Ændret. |
| Kørsel | ID, Dato, Formål, Fra, Til, Km, Medtag i skatteoversigt, Klinik-tur, Oprindelse, Oprettet/Ændret. |
| Lister | Sessionselement / Udgiftskategori / Betalingsmetode with id, name, hidden, order. |
| Indstillinger | Locations, route, km, flags – plus one technical row with the settings as JSON. |
| Info | Format name, format version, data version, export time, **checksum (SHA-256 fingerprint)**. |

Formatting: real dates (Excel serial numbers with `dd-mm-yyyy`), numeric money (`#,##0.00` – shown
with Danish separators in Danish Excel), frozen header rows, auto filters, sensible column widths.
The file is generated by `Core/Excel/XlsxWriter.cs` and validated in the test suite with the
official Open XML SDK validator (Office 2019 schema).

### Restore from the workbook ("Excel-only restore")

Supported for the app's **own, unmodified** workbook only:

1. The workbook is read (inline or shared strings – re-saving in Excel is tolerated).
2. The complete dataset is rebuilt from the structured sheets.
3. Its fingerprint (`DataSerializer.Fingerprint`, order- and trailing-zero-independent SHA-256 of
   the canonical JSON) must equal the checksum on the Info sheet. **Any edited value fails** with
   "Regnearket er blevet ændret efter eksporten …". A modified spreadsheet is never silently used.
4. Receipts are not in a workbook: expenses are restored without attachments, with an explicit warning.
5. It is a full replacement, exactly like a ZIP restore.

Two-way Excel editing/synchronisation is not supported (by design).

## Authority-oriented report – `Regnskabsoversigt-YYYY.xlsx`

"Regnskabsoversigt – materiale til skatteopgørelse". For one year:

| Sheet | Content |
|---|---|
| Oversigt | Key figures, disclaimer (not approved by authorities, no VAT calculated, driving is Sofie's own classification), per-month table, expenses per category, payments per method. |
| Sessioner | Reference (S-YYYY-NNN), date, services (elements), hours, price, paid, outstanding. |
| Betalinger | Payment date, amount, method, session reference and date. |
| Udgifter | Reference (U-YYYY-NNN), date, category, description, amount, receipt yes/no. |
| Kørsel | Only trips marked "Medtag i skatteoversigt": date, purpose, from, to, km. |

It contains **no client nicknames and no internal ids** – not in cells, hidden columns, sheet names,
comments or document properties (title "Regnskabsoversigt YYYY", author "Sofies Univers").
`ExcelTests.Tax_report_excludes_nicknames_and_ids_everywhere` scans every part of the file.
Note: expense descriptions and trip purposes are Sofie's own free text and are included; she should
not put client names there (the help page says so).

## Backup – `Sofie-Backup-YYYY-MM-DD.zip`

```
Sofie-Backup-2026-10-28.zip
├── Sofies-Regnskab.xlsx                ← the complete private workbook (for people)
├── Kvitteringer/
│   ├── 2026-01-03_U-2026-001_Materialer.jpg
│   └── 2026-02-01_U-2026-002_Lokaleleje.pdf
├── Data/sofies-univers-data.json       ← AUTHORITATIVE for restore (complete AppData)
├── Backup-info.json                    ← versions, counts, SHA-256 of every file
└── LÆS MIG.txt                         ← Danish explanation
```

`Backup-info.json`:

```json
{
  "format": "sofies-univers-backup",
  "formatVersion": 1,
  "dataVersion": 1,
  "appVersion": "1.0.0",
  "createdAt": "2026-10-28T09:00:00+00:00",
  "dataFile": "Data/sofies-univers-data.json",
  "dataSha256": "…",
  "workbookFile": "Sofies-Regnskab.xlsx",
  "workbookSha256": "…",
  "attachments": [ { "attachmentId": "…", "path": "Kvitteringer/…", "sizeBytes": 123, "sha256": "…" } ],
  "counts": { "sessions": 120, "payments": 110, "expenses": 25, "receipts": 16, "trips": 90, … }
}
```

**Authoritative file:** `Data/sofies-univers-data.json` (with the receipt files). It is the exact
JSON form of the complete dataset, and the same migration code that upgrades IndexedDB upgrades it.
The workbook is complete and useful for people, but JSON avoids any risk from spreadsheet round-trips.

### Versioning

* `formatVersion` – the ZIP layout. A backup with a higher version than the app supports is refused
  ("lavet med en nyere version af appen").
* `dataVersion` – the JSON shape. Older versions are migrated on restore; newer are refused.

### Validation before anything changes (`BackupReader.Read`)

1. ZIP can be opened; size and entry-count limits (600 MB / 20 000 entries).
2. `Backup-info.json` exists, has the right format name and supported versions.
3. Data file exists and its SHA-256 matches.
4. Data deserialises and migrates.
5. Every referenced receipt exists, its size and SHA-256 match `Backup-info.json` and the expense.
6. `DataValidator`: unique ids, required fields, ranges, 1–3 existing elements, payments reference
   existing sessions/methods, no overpayment, expenses reference existing categories, at most one
   clinic trip per date, valid settings and route.

Only a fully valid backup reaches the confirmation screen.

### Restore procedure (full replacement, never a merge)

1. Choose the file → validated as above (nothing is written).
2. Summary: current counts vs. counts in the file, backup date and app version, warnings.
3. Explicit warning that all current data will be replaced.
4. Optional safety backup of the current data (same two-tap backup flow).
5. Checkbox "Jeg forstår …" and a final confirmation dialog.
6. Receipts are staged, then one IndexedDB transaction replaces all record stores and removes
   receipts that are no longer referenced.
7. Success → home screen; failure → "Gendannelsen mislykkedes. Dine nuværende data er ikke ændret."

Restoring the same backup repeatedly gives the same result (no duplicates). After a restore,
`lastConfirmedAt` is set to the backup's creation time (that file demonstrably exists).

### Backup status and the weekly reminder

The app separates three facts, because the share sheet cannot prove a file was saved:

* **Lavet** – the ZIP was generated (`lastGeneratedAt`).
* **Delt/hentet** – the share sheet or download was started (`lastSharedAt`).
* **Bekræftet** – Sofie tapped "Ja, backuppen er gemt" (`lastConfirmedAt`).

The home screen card appears when there are changes after the last confirmed backup and that backup
is at least 7 days old (or, before the first confirmed backup, one day after the first registration).
"Påmind mig senere" hides it for 3 days.
